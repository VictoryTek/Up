## What's Changed

### Bug Fixes
- **Update All re-disables when nothing is left to update**: After an update run completes, the button returns to its greyed-out state instead of staying clickable. A backend that updated cleanly now reports zero pending updates; the button only stays active if an un-skipped source still has outstanding updates (for example one that errored out).
- **No scroll bar when an update starts**: The progress bar now reserves its space permanently and fades in on start rather than being inserted into the layout, so pressing "Update All" no longer pushes the page down and introduces a vertical scroll bar.
- **Window fits smaller screens**: The window now sizes itself to the monitor instead of opening at a fixed 760×730, and a short-screen layout tightens the hero area, section spacing and margins when there isn't much vertical room. The Terminal Output panel now starts as a compact box that grows with content instead of reserving a tall empty area. The Update page no longer opens with a scroll bar on a 1280×800 display.

### Improvements
- **Clear "update complete" indication**: When an Update All run finishes, the status line under "System Updater" turns green — "✓ System is up to date", "✓ Update complete" when updates still remain, or a red "Update finished with errors — see the log below". The message clears when the next check or update starts. This replaces the earlier full-width banner, which wasted vertical space in a small window.

### Internal
- `UpdateRow::set_status_success` records a zero available-count so the window can re-gate the Update All button from row state without re-running the availability check.
- `UpWindow::default_window_size` derives the initial size from `gdk::Monitor` geometry, and a `max-height: 740px` `AdwBreakpoint` toggles a `.compact` style class for the tightened layout.
